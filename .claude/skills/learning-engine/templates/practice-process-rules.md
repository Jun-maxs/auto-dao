# Practice Process Rules

这些规则给 AI 使用，不直接整段写入学习者主文档。它们用于把“学知识”压到“做出可验证结果”的闭环里。

## 核心原则

学习一项技能时，不先问“我要学多少知识”，先问“我要做出什么结果”。但结果不是终点，必须继续追问：我能解释吗、能修改吗、能排错吗、能迁移吗？

默认闭环：

```text
结果定义 -> 最小闭环 -> 按需补课 -> 刻意练习 -> 反馈校准 -> 复盘沉淀 -> 迁移挑战
```

## 结果定义

- 禁止把目标写成“学会 X”“掌握 X”“深入理解 X”。
- 目标必须是可见成果：能跑、能测、能解释、能复现、能迁移。
- 每个结果必须带验收标准，至少覆盖“做出来”“解释得清”“能改一处”“能排一个错”。

好目标示例：

```text
用 USART1 每秒发送一次传感器数据，并能用串口助手看到结果。
能解释波特率、TX/RX 交叉连接、GPIO 复用和中断接收的作用。
```

## 最小闭环

每个实践任务必须形成：

```text
输入 -> 处理 -> 输出 -> 反馈
```

STM32 常见闭环示例：

| 知识点 | 最小闭环 |
|---|---|
| GPIO 输出 | 写代码 -> LED 亮灭 |
| GPIO 输入 | 按键输入 -> LED 状态改变 |
| UART | STM32 发送数据 -> 串口助手显示 |
| TIM | 定时器中断 -> LED 周期闪烁 |
| PWM | 定时器输出 -> 示波器看到波形 |
| ADC | 电压变化 -> 串口打印数值变化 |
| DMA | 外设数据 -> 自动进入内存数组 |
| I2C | 读取传感器 ID -> 串口显示 |
| SPI | 读取 Flash ID 或驱动屏幕 -> 得到可观察反馈 |

## 按需补课

- 项目卡住时，只补当前闭环需要的局部知识。
- 补课必须回答“这个知识解决当前哪个卡点”，不写泛泛背景。
- 学完后立刻回到闭环，不把补课扩展成完整 deep 文档。

## 反馈校准

每个实践任务至少指定一种反馈来源：

- 机器反馈：编译、串口、LED、示波器、寄存器标志位、buffer 更新。
- 专家反馈：代码可维护性、架构、实验说明、排查路径。
- 用户反馈：对方是否看懂、是否愿意使用、是否被说服。

完成不等于掌握。只有通过反馈确认质量，才算闭环完成。

## 复盘沉淀

每个实践任务结束时，要求学习者写 4 行复盘：

```text
我做出了什么结果：
它依赖哪些核心概念：
我踩了哪些坑：
下次如何排查或迁移：
```

## 间隔练习

- 完成闭环后，把易错点加入 review queue 或后续 practice-pack。
- 复习题优先考“能否不看教程复现”“能否解释为什么”“能否换场景迁移”。
- 不以一次做出来为掌握；以隔天、隔三天仍能复现和解释为掌握信号。
